# Refactoring UI.py - تقسیم‌بندی به فایل‌های کوچکتر

## خلاصه تغییرات

فایل `ui.py` که قبلاً 3157 خط داشت، به 10 فایل کوچکتر و منطقی تقسیم شده است.

## ساختار جدید

### فایل اصلی
- **`main.py`** - فایل اصلی Flask که تمام blueprint ها را import و register می‌کند

### فایل‌های Routes (در پوشه `routes/`)
1. **`vision_routes.py`** (390 خط) - API های سیستم بینایی
2. **`warehouse_routes.py`** (184 خط) - مدیریت انبارها
3. **`product_routes.py`** (153 خط) - مدیریت محصولات
4. **`loading_routes.py`** (705 خط) - عملیات بارگیری
5. **`unloading_routes.py`** (341 خط) - عملیات تخلیه
6. **`shipment_routes.py`** (216 خط) - مدیریت محموله‌ها
7. **`operation_type_routes.py`** (167 خط) - انواع عملیات
8. **`vision_server_routes.py`** (226 خط) - سرورهای بینایی
9. **`ssh_routes.py`** (101 خط) - عملیات SSH

### فایل‌های پشتیبان
- **`ui_backup.py`** - نسخه پشتیبان از فایل اصلی `ui.py`

## مزایای ساختار جدید

### 1. قابلیت نگهداری بهتر
- هر بخش در فایل جداگانه‌ای قرار دارد
- پیدا کردن و ویرایش کد راحت‌تر است
- خطاها در بخش‌های مختلف مجزا هستند

### 2. خوانایی بیشتر
- کد به راحتی قابل فهم است
- هر فایل مسئولیت مشخصی دارد
- ساختار پروژه واضح‌تر است

### 3. قابلیت توسعه
- اضافه کردن API های جدید راحت‌تر است
- تغییرات در یک بخش روی بخش‌های دیگر تأثیر نمی‌گذارد
- امکان کار همزمان چندین توسعه‌دهنده

### 4. تست بهتر
- هر بخش را می‌توان جداگانه تست کرد
- تست‌های unit کوچکتر و سریع‌تر هستند
- عیب‌یابی راحت‌تر است

### 5. مدیریت کد
- امکان استفاده از Git branches برای بخش‌های مختلف
- Code review راحت‌تر است
- امکان استفاده از linting tools مختلف برای هر بخش

## نحوه استفاده

### اجرای سرور
```bash
cd backend
python main.py
```

### اضافه کردن route جدید
1. فایل مناسب را در پوشه `routes/` انتخاب کنید
2. route جدید را اضافه کنید
3. در صورت نیاز، blueprint جدید ایجاد کنید
4. آن را در `main.py` register کنید

### Import کردن blueprint
```python
from routes.vision_routes import vision_bp
app.register_blueprint(vision_bp)
```

## نکات مهم

### 1. حفظ سازگاری
- تمام API endpoints قبلی حفظ شده‌اند
- هیچ تغییری در عملکرد API ها ایجاد نشده
- فقط ساختار کد تغییر کرده است

### 2. مدیریت وابستگی‌ها
- هر فایل فقط import های مورد نیاز خود را دارد
- از circular imports جلوگیری شده
- وابستگی‌ها به حداقل رسیده

### 3. Error Handling
- هر بخش error handling مخصوص خود را دارد
- خطاها به درستی به کاربر برگردانده می‌شوند
- Logging مناسب برای هر بخش
